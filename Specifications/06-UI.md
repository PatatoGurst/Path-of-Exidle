## 5.1 Color System

### Overall Theme

Dark fantasy aesthetic inspired by the PoE official website: near-black backgrounds, gold typography, and crimson accents. All colors are chosen to minimize eye strain during long sessions.

### Background Ramp

| Role | Hex | Usage |
|---|---|---|
| Page background | `#0c0b09` | Root / outermost layer |
| Panel / Sidebar | `#131108` | Navigation sidebar |
| Card / Content area | `#1c1a10` | Main content panels |
| Elevated surface | `#252010` | Modals, tooltips, raised cards |

### Gold — Primary Text & Accents

| Role | Hex | Usage |
|---|---|---|
| Primary gold | `#c9a84c` | Headings, labels, nav text |
| Light gold | `#e8d08a` | Hover glow, highlighted text |
| Muted gold | `#7a5c1e` | Borders, dividers |
| Subtle gold | `#3a2e14` | Subtle tinted backgrounds |

### Crimson — Interactive & Combat Energy

| Role | Hex | Usage |
|---|---|---|
| Deep crimson | `#8b1a1a` | Button gradient start |
| Active crimson | `#c0392b` | Hover state, danger indicators |
| Dark crimson | `#3a0e0e` | Button gradient end |

### Buttons (PoE-inspired)

- **Default**: gold text (`#c9a84c`) on a left-to-right crimson-to-black gradient (`#8b1a1a` → `#1a0808`), gold border (`#7a5c1e`)
- **Hover**: gold text brightens to `#e8d08a` with a subtle glow, gradient shifts to `#c0392b` → `#3a0e0e`, border brightens to `#c9a84c`
- **Active / pressed**: slight scale-down, gradient darkens

### Item Rarity Colors

| Rarity | Text color | Hex | Background tint |
|---|---|---|---|
| Common | Light gray | `#d0d0d0` | `#1e1e1e` |
| Magic | Steel blue | `#6fa8dc` | `#0d1a2e` |
| Rare | Gold-yellow | `#e8c84a` | `#2a1e00` |
| Unique | Orange-red | `#e05a2b` | `#2a0a0a` |

### HUD Elements

| Element | Color | Notes |
|---|---|---|
| Life Orb fill | Deep red radial gradient — `#8b1a1a` → `#3a0505` | Border: `#6b1212` |
| Mana Orb fill | Deep blue radial gradient — `#1a3a8b` → `#050a3a` | Border: `#12286b` |
| XP bar fill | Amber gradient — `#e8b84b` → `#b8861c` | Background: `#1a1208` |
| XP bar border | `#7a5c1e` | Matches muted gold |

## 5.2 Design Principles

- **Readability first**: numbers, stats and nodes must be clear and comparable at a glance
- **Constant feedback**: every action (loot, craft, level-up) must produce a visual response
- **Frictionless management**: automation must be accessible and configurable without unnecessary complexity
- **Dark aesthetic**: visual direction inspired by PoE's dark fantasy tone

## 5.4 Header

- Thin bar fixed at the top of the screen
- Contains: **game name and/or logo** — left-aligned or centered
- Must remain minimal — no character data
- Optional: settings / options icon anchored to the top-right corner

## 5.5 Left Sidebar Navigation

### Behavior

- **Always visible** — the user toggles manually between expanded and collapsed states
- Toggle button (e.g. `‹` / `›` chevron) placed at the top or bottom of the sidebar
- Smooth CSS transition on toggle

### States

| State | Width | Content |
|---|---|---|
| **Expanded** | ~200px | Icon + text label per menu item |
| **Collapsed** | ~56px | Icon only; label shown as tooltip on hover |

### Menu Items (V1)

| Icon | Label | Page content |
|---|---|---|
| 🎒 | Inventory | Item grid, equipment slots, crafting queue |
| 🗺️ | Map | Zone selection, active combat view |
| 🌐 | Skill Tree | Passive node graph, point allocation |
| 🔺 | Ascension | Ascension status, Ascension Tree |

> Icons are placeholders — final iconography to be defined during UI implementation.

### Design Notes

- Active page is highlighted in the sidebar (distinct background or accent color)
- Sidebar background should visually contrast with the main content area
- No nested sub-menus in V1

## 5.6 Footer HUD Bar

Persistent bar fixed at the bottom of the viewport. Always visible regardless of the active page. Directly inspired by PoE's in-game HUD.

### Life & Mana Orbs

| Element | Position | Description |
|---|---|---|
| **Life Orb** | Bottom-left | Circular gauge — current / max HP |
| **Mana Orb** | Bottom-right | Circular gauge — current / max Mana |

- Visual style: circular fill (PoE-style), color-coded (red for Life, blue for Mana)
- **The orbs are taller than the footer bar** and overflow upward into the content area, using `position: absolute` with a negative top offset — directly replicating PoE's in-game HUD behavior
- The main content area must reserve bottom padding equal to the footer height so that orb overflow never obscures interactive content
- Current and max values displayed inside the orb or on hover

### XP Bar

- Horizontal bar occupying the **majority of the footer width**, centered between the two orbs
- Divided into **10 sub-segments of 10% each**, with visible separators between them
- Fills progressively left-to-right as XP accumulates within the current level
- Resets visually at each level-up
- Color: golden / amber (PoE-inspired)

### Character Name & Level

- Displayed within the footer zone, near the XP bar (above or below it — to be decided during implementation)
- Format: `Character Name — Level XX`
- Compact typography, must not clutter the HUD

---

## 5.7 Main Content Area

- Fills all remaining space between the sidebar (left), header (top), and footer HUD (bottom)
- Renders the currently active page
- Scrollable vertically if content overflows
- Each page (Inventory, Map, Skill Tree) defines its own internal layout

## 5.9 Map Tab — Layout & Combat View

The Map tab is the primary gameplay view. It is split into two states: **zone selection** and **active combat**.

### Zone Selection View

- Displays the current Act with all 12 zones listed (grid or vertical list)
- Each zone shows its state: `locked`, `unlocked`, `completed`, `active`
- Completed zones display a completion indicator (e.g. checkmark, distinct color)
- Locked zones are visible but grayed out and non-interactive
- Selecting an unlocked or completed zone enters the **active combat view**
- An Act selector allows switching between Acts (only Acts with at least one unlocked zone are accessible)

### Active Combat View

Once a zone is entered, the view switches to the combat display:

**Pack overview bar (top of the view)**

- A horizontal strip showing **one icon/indicator per fight pack** in the zone
- Each indicator reflects the pack's state: `pending`, `active`, `defeated`
- **Hovering** a pack indicator reveals a tooltip with:
  - Number of monsters in the pack
  - Each monster's name, rarity (color-coded), and tier
- The current active pack is highlighted
- The boss fight (last pack) is visually distinct (Unique color, special icon)

**Combat area (main section)**

- Displays the **current one-on-one fight**: player character vs. active monster
- Player side (left): name, HP bar, current HP / max HP
- Monster side (right): name, rarity badge, HP bar, current HP / max HP
- Combat log below: scrolling feed of events (hit, miss, loot, death)
- If the player dies: brief death feedback, then zone resets and returns to Fight 1

**V1 constraints:**
- Even if a pack contains multiple monsters, combat is strictly sequential (one at a time)
- No player interaction required — all combat is automatic

## 5.10 Skill Tree Tab — Layout & Interaction

The Skill Tree tab renders a **full-area interactive canvas** that fills the entire main content zone. The DOM UI (header, sidebar, HUD) floats above it.

### Canvas Layer

- Rendered by **PixiJS** (WebGL), initialized via a React `ref` on a `<canvas>` element
- PixiJS app instance lives outside the React render cycle — React owns state, PixiJS owns rendering
- Panning via drag, zooming via scroll or pinch — implemented through PixiJS container transforms
- Background: dark textured surface consistent with the game's color system (`#0c0b09` base)
- Thematic regions delimited by subtle background zones or faint labels, rendered as PixiJS Graphics objects

### Node Rendering

| Node type | Shape | Size |
|---|---|---|
| Small | Circle | Small |
| Notable | Circle | Medium, distinct border |
| Keystone | Circle | Large, ornate border |

Node color by state:

| State | Color |
|---|---|
| `allocated` | Gold fill (`#c9a84c`) |
| `available` | Dimmed gold outline |
| `planned` | Amber highlight (planning mode) |
| `locked` | Dark gray, low opacity |

Edges (connections between nodes) are rendered as lines — gold for allocated paths, dark gray for unallocated.

### Tooltip (on hover)

Appears near the hovered node, contains:
- Node name and type badge
- Full bonus description
- State (`Available`, `Locked`, etc.)
- Point cost to allocate

### Confirmation Panel (on click)

A small panel anchored near the selected node or in a fixed corner:
- Node name, type, full description
- Current state and cost
- **Allocate** button (disabled if no points or node not available)
- **Refund** button (only on `allocated` nodes — shows Respec Resource cost)

### HUD Integration

- Available skill points displayed prominently in the footer HUD or near the tree header
- Points counter updates immediately on allocation or refund

## 5.11 Combat Log

The combat log is a **scrollable feed** displayed within the Map tab, below or beside the active combat area. It traces all events occurring during a zone run in chronological order.

### Log Event Types

Each event type can be **individually toggled on or off** by the player via a filter panel on the log:

| Event type | Example output | Default |
|---|---|---|
| Player deals damage | `You hit Skeleton Warrior for 42 physical damage` | On |
| Enemy deals damage | `Skeleton Warrior hits you for 18 physical damage` | On |
| Player evades | `You evaded Skeleton Warrior's attack` | On |
| Enemy evades | `Skeleton Warrior evaded your attack` | On |
| Enemy death | `Skeleton Warrior slain` | On |
| Player death | `You have been slain — zone reset` | On |
| Pack cleared | `Pack 2 cleared — advancing to Pack 3` | On |
| Loot drop | `Dropped: Iron Sword (Magic)` | On |
| Zone completed | `Zone completed: Forgotten Cellar` | On |

### Log Behaviour

- New entries append at the **bottom** of the log; the log auto-scrolls to the latest entry unless the player has manually scrolled up
- If the player scrolls up, auto-scroll pauses — resumes when the player scrolls back to the bottom
- Log entries are **not persisted** across sessions — the log is cleared on zone exit or browser reload
- Maximum retained entries: **500 lines** (oldest entries are dropped when the cap is reached)
- Log is only active when the **combat timer is running**

## 5.12 Notification System

A **floating notification panel** anchored to the **lower-right corner** of the viewport, above the HUD footer. Notifications appear on specific game events and are independent of the active tab.

### Notification Events (V1)

| Event | Content | Priority |
|---|---|---|
| Player death | `You have been slain` | High |
| Notable loot drop | `[Item name] dropped` (Rare or Unique only) | Medium |
| Level up | `Level XX reached` | Medium |
| Zone completed | `Zone completed` | Low |
| Auto-craft stopped | `Auto-craft stopped: currency depleted` | Medium |

### Stacking & Dismissal

- Notifications **stack vertically**, newest at the bottom
- Each notification **auto-dismisses** after a configurable duration (default: 4 seconds)
- The player can **manually dismiss** a notification by clicking it
- On hover: dismissal timer **pauses** (configurable — hover-to-pause can be disabled in settings)
- Maximum visible notifications at once: **5** — oldest are dropped if the cap is exceeded before dismissal
- The entire notification panel can be **toggled off** in settings (all notifications suppressed)

### Notification Design

- Compact card: icon (event type) + short message + rarity color badge for loot notifications
- Slide-in animation from the right on appear; fade-out on dismiss
- High priority notifications (player death) use a distinct visual treatment (crimson border)
- Notification settings saved in `irpg_settings` under `ui.notifications`

### V2+ — Sound

Each notification event will have a **bindable sound effect** triggered on fire. Sound system design deferred to V2+. Settings will include per-event volume and a global mute toggle.

- **Item tooltip**: full affix display with comparison against the currently equipped item
- **Stats panel**: all character statistics calculated and displayed in real time
- **Progress indicators**: level-up animation, zone unlock highlight, ascension available badge
